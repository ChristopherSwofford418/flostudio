# Email database contract

Migration: `supabase/migrations/20261109_email_campaigns.sql`. **Applied additively to Flo Studio on November 9, 2026 after isolated validation. Twenty-five active apps have disabled draft configurations. No OAuth connection, scheduler activation, paid provider call, or live send was performed.**

## Exact endpoint contract

`email_campaigns`: `id`, `workspace_id`, `product_id`, `name` default `Daily app email`, `daily_limit` default100 constrained1–100, `timezone` defaultUTC, `send_hour` default9, `send_minute` default0, `state` draft/paused/approved (defaultdraft), `sending_enabled` defaultfalse, `recipient_cooldown_days` default30/minimum30, `sender_name`, `postal_address`, `ad_link`, `audience`, `language` defaulten, `approved_by`, `approved_at`, `created_at`, `updated_at`. Authenticated admin JWT writes are required for approval. Setting approved sets the per-campaign sending flag true; **account and workspace-connection gates remain false until separately enabled, and the API environment gate must remain false now**. Editing configuration/content invalidates campaign and all draft approvals, disables campaign sending, and returns campaign to draft. Pause disables sending.

`email_contacts`: `id`, workspace/product IDs, normalized immutable `email`, `organization`, `status` candidate/opted_in/unsubscribed, `consent_evidence`, `consent_recorded_by`, `consent_recorded_at`, `source_url`, `source_evidence`, `last_contacted_at`, timestamps. Consent format: `{ "method": "operator_recorded", "reference": "operator-supplied proof reference", "recorded_at": "ISO timestamp" }`. All three evidence fields are nonblank strings; timestamp must parse and not be future. Trigger records the actual authenticated admin UUID/time and disallows later spoofing of those audit columns. This is manually recorded consent evidence, not provider verification. Autonomous service-role candidate-to-opt-in writes are rejected because no human JWT exists. `source_url` must be HTTP(S) when supplied; research importer must require source links/evidence, while manually recorded contacts may have no research URL.

`email_drafts`: `id`, workspace/product/campaign/contact IDs, `subject`, `body`, `status` draft/approved, `approved_by`, `approved_at`, timestamps. Draft edits reset approval. Claims snapshot approved subject/body/sender so later edits cannot change an already claimed message. `email_send_queue`: those scoped IDs plus `draft_id`, `email`, `scheduled_day`, status prepared/claimed/sent/unknown/failed/suppressed, `claim_token`, `claimed_at`, `finished_at`, `provider_message_id`, `subject_snapshot`, `body_snapshot`, `sender_snapshot`, timestamps. Queue writes are RPC-only, including for service_role. `email_suppressions`: `workspace_id`, normalized `email`, `reason`, `created_at`; workspace-wide. Admin insertion allowed; deletion/re-opt-in is not exposed. `email_cron_runs`: `id`, workspace/product/campaign IDs, `scheduled_day`, `claimed_at`; permanent unique campaign/day claims.

### Service-only Gmail and OAuth tables

| Table | Exact columns and server rules |
| --- | --- |
| `email_gmail_accounts` | `account_key` primary key (64lowercase hex server HMAC of stable Google account subject, shared across every workspace), `daily_budget` default400/range1–2000, `sending_enabled` defaultfalse, `created_at`. Insert account before workspace connection. |
| `workspace_gmail_connections` | `workspace_id` primary key, `account_key` FK, `email`, `configured` defaultfalse, **`sending_enabled` defaultfalse**, `daily_budget` default400/range1–2000, `encrypted_credentials` JSON envelope, `created_by` authenticated admin UUID (validated by server), `created_at`, `updated_at`. |
| `email_oauth_states` | `state_hash` primary key (64lowercase hex SHA256), `workspace_id`, `created_by`, `expires_at`, `consumed_at` nullable, `created_at` defaultnow. Expiry must be after created_at and at most15minutes later. No plaintext state stored. |
| `email_unsubscribe_tokens` | `token_hash` primary key (64lowercase hex SHA256 of at least32random bytes), `workspace_id`, exact normalized `email`, optional `expires_at`, `created_at`. Tokens never exposed through client table read. |
| `email_quota_reservations` | `queue_id` primary key, `account_key`, `reserved_at`. Service SELECT only; RPC inserts. Durable reservations are never automatically refunded. |

Encrypted credential envelope must contain `version:1`, `algorithm:'aes-256-gcm'`, nonempty `iv`, `tag`, `ciphertext`. Additional `workspaceId`/AAD metadata is permitted. The API must implement encryption/decryption with a server-only, domain-separated root key and bind ciphertext to workspace AAD. The database validates envelope shape, not cryptographic authenticity. Never return ciphertext or root keys to client; derive status `{configured,email,daily_budget,sending_enabled}` in the server after admin authorization. `emailDb` service calls can SELECT/INSERT/UPDATE/DELETE secret metadata except quota ledger; no service direct writes to queue/run/public tables.

## Service RPC signatures

| RPC | Return and semantics |
| --- | --- |
| `email_prepare_queue(p_campaign_id uuid, p_contact_id uuid, p_draft_id uuid, p_scheduled_day date)` | uuid or null on cross-app recipient/day dedupe; requires approved campaign/draft, same app and workspace, opted-in unsuppressed recipient and campaign's current local date. Preparing does not send or reserve quota. Existing exact campaign/contact/day row is returned on repeat, even if terminal; it is not retried. |
| `email_claim_send(p_queue_id uuid)` | `email_send_queue` composite or null. Atomic claim, app local-day quota, Gmail rolling24h shared quota, workspace-wide recipient cooldown, local send time/date, opt-in, suppression, human campaign/draft approval and campaign/account/connection gate rechecks. Snapshot content is returned. |
| `email_finish_send(p_queue_id uuid, p_claim_token uuid, p_outcome text, p_provider_message_id text default null)` | void. Outcome must be sent/unknown/failed; sent requires provider acceptance message ID. Wrong claim token rejected. Terminal outcome immutable and same-outcome repeats idempotent. Failed/unknown never automatically become prepared. |
| `email_claim_daily_run(p_campaign_id uuid)` | uuid or null. Campaign, account and connection must be enabled/configured, reviewed, and local timer due. Durable unique campaign/day claim; no lease reclaim. |
| `email_unsubscribe(p_token_hash text)` | boolean; service endpoint hashes raw token. Resolves exact workspace/email from private token row and atomically inserts suppression, marks all matching app contacts unsubscribed, suppresses prepared queue. Invalid/expired token returnsfalse. Token reuse remains idempotent; no arbitrary recipient ID input. |
| `email_consume_oauth_state(p_state_hash text, p_user_id uuid)` | workspace uuid or null. Atomic one-time state consumption with expiry/user check; server gets user ID from independently verified JWT. |
| `email_pause_workspace(p_workspace_id uuid)` | void. Service-only narrow pausing for reconnect/disconnect/permanent OAuth failures. Sets all workspace campaigns paused and disables their sending; suppresses prepared queue without retracting or retrying claimed/unknown items. Does not grant service_role blanket campaign UPDATE. |

## Isolation and operational limits

All product-bearing foreign keys are composite workspace/product references, including queue→campaign, queue→contact/email and queue→draft/campaign/contact. An additive unique index on products(workspace_id,id) supplies the existing schema's missing composite candidate key. Members/owners/admins can read public email tables; admin-only insert/update RLS applies to campaign/contact/draft tables. Secret/token/quota tables have no client privileges or policies. PUBLIC/anon/authenticated execute is revoked on every definer RPC and trigger; only service_role can execute queue/cron/unsubscribe/OAuth RPCs. Every SECURITY DEFINER function fixes search_path to the empty string. Existing provider-key-vault JWT authorization helpers should be used before service writes; never trust a browser-provided user ID.

Queue preparation, dispatch and daily-run claims reject products whose `source_facts.archived` is true. Draft content edits reset approval and suppress any prepared queue entry; campaign content edits invalidate all drafts, which likewise suppress prepared entries. Suppressed same-recipient/day dedupe records remain durable, so reapproval does not resurrect them that day. Already claimed entries retain their immutable snapshots; no edit or pause can retract an external in-flight request. The server should display this conservatively rather than suggesting it stopped delivery.

Shared account budget is the minimum of the account budget and every **configured, sending-enabled** connection budget; a connection's configured budget can never increase the effective account budget. Defaults remain400; the authorized API may explicitly choose a Workspace budget up to2000, preferably1800 to reserve headroom for other usage. Database cannot verify Gmail account class, external Gmail usage, or stable subject/account HMAC correctness. There is no auto-upgrade, provider switch or paid action.

All claimed attempts count for rolling24h and app local-date quotas, including failed/unknown outcomes. Workspace-wide recipient/day queue uniqueness and at least30-day claim cooldown stop different apps from blasting the same person. Claimed and unknown attempts block that recipient indefinitely until explicit future manual reconciliation is designed; there is no automatic uncertain-send retry. The worker owns fair allocation across eligible apps; SQL guarantees only hard caps, not fair distribution. For25apps, a full budget of2000 implies80/app and1800 implies72/app before eligibility, cooldown and quota checks; per-app hard cap remains100.

A claim commits before the network request; DB atomicity cannot retract an already dispatched Gmail request if opt-out arrives after claim. Worker must recheck suppression immediately before dispatch, include raw unsubscribe link/header, and mark any timeout or uncertain provider result unknown. Lost workers leave claimed items non-retryable. Concurrent mutations may deadlock under safe workspace/account locks and abort; retry only the database mutation before dispatch, never an uncertain external request. Account setting changes are serialized with account-row quota claims; connection changes use row locks. DST repeated hours produce only one local-day run; skipped times are due on the first later poll that same local day. Missed prior days are not backfilled. No cron job is created; the future app-native Vercel worker owns polling after explicit activation.

## Validation

`node --test tests/email-migration.test.mjs` runs four dependency-free static contract tests. Optional `EMAIL_TEST_PGLITE_MODULE=/absolute/path/to/@electric-sql/pglite/dist/index.js node --test tests/email-migration.test.mjs` additionally creates a disposable in-memory PostgreSQL instance and synthetic auth/workspace/product tables, applies this migration there, and exercises RLS, cross-app FKs, consent proofs/audit identity, approvals/invalidation, shared quota, disabled gates, queue/run dedupe, unknown terminal behavior,30-day cooldown, suppression and one-time OAuth state. The isolated run passed **5/5 tests**. No production database was contacted or modified. PGlite is installed outside the repository for task validation only; it is not a project dependency. Multi-session production concurrency and provider behavior require a separate staging integration review before activation.
